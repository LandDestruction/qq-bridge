# 跨群「认人」一页设计（D42）

## 要解决的问题
真机：A 群问「你认识隔壁的哦鲸鲸吗」→ 答「不认识，换个群就断片」。
数据其实有（群 100000004 里 17 条发言、好感度台账有她），但**注入没有**：
摘要只压缩「最近约 10 条入站」，20~30 分钟换一批；好感度只在「本人本轮说话」时注入。
结论：不要调大摘要窗口，做「长期人物档案 + 命中才召回」。

## 数据模型（`state/people.json`，按 userId 跨群统一）
```
{ version:1, updatedAt, backfilledAt, people: {
  "<userId>": {
    userId, aliases:[{name, source:'card'|'ledger'|'sender', scope, lastSeenAt}],
    groups:{ "<group:xxx|private:xxx>": {count, first, last} },
    firstSeenAt, lastSeenAt, msgCount,
    recentTopics:[{text, groupId, at}],              // 人物级话题（关键词短语，≤6 字，最多 3 条）
    topicHits:{ "<phrase>": {count, weight, lastAt, groupId} }, // 内部聚合，用来排序
    affinityRef:{ file:'state/affinity.json', userId }   // 只引用，不复制分数
  } } }
```
- 别名来源三处：群名片缓存（card）> 好感度台账 name（ledger）> 历史消息 sender（sender）。
  这就是治「台账 name 为空、跨群拿不到名字」的地方。
- **话题必须说得出**（用户 12:47 补的验收口径：「认名字 和 还要说聊过什么」）：
  `recentTopics` 取**本人**发言里的关键词短语（按虚词切词块，命中技术/工作类词的优先），
  **不是整群摘要、不是原话**；没有就空着，绝不拿群里的话题冒充她的。
  排序：重复次数 > 技术词 > 出处消息长度 > 词块质量 > 新旧。
- **时间线（D48）**：话题注入时带相对时间与群来源，如 `打包脚本（昨天，另一个群）`；
  时间取自她**当时发言**的 `at`（不是档案生成时间），用 `src/relative-time.js` 按日历天判断跨天
  （差 2 小时但跨天必须说「昨天」）。缺时间写「时间不详」，并允许说「记不清」——
  **不许编时间、不许把无时间片段当成刚发生**。
- 容量：人数 ≤500（按 lastSeenAt 淘汰最旧）、每人别名 ≤5、话题候选 ≤30 / 保留 3、
  90 天未出现**降权不删**（不再进召回、档案仍保留）。
- 印象**不落 people.json**：召回时现读 `socialV2.globalImpressions` / 会话 `memberImpressions`
  （qq_memory_append 的真源），不造第三份记忆。

## 召回时机（只在需要时）
1. 本轮最新入站消息里出现已知别名（完整名，或 ≥3 字后缀——「聪明头哦鲸鲸」→「哦鲸鲸」）。
2. 没有别名命中、但句子里有「隔壁/别的群/其他群/你们群」→ 只给「你在别处认识的人：A、B、C」名单，
   并明确「只认得出这些」。
3. 都没命中 → **返回空串，0 字符注入**（prompt 总长不变）。

## 字符预算
- 每人一块，最多 2 人；整段 ≤200 字符（配置可调），超长截断。
- 注入顺序：**名字/出现次数 → 话题 → 印象 → 口径句**；预算不够时按
  「砍印象 → 砍第二个话题 → 砍话题」降级，**名字 + 至少 1 个话题永远保住**。
- 名单模式最多 3 个名字。
- 没有命中就是 `''`，不产生空行（prompt-parts 里 people 段 chars=0 会被过滤）。

## 隐私（B 档）
- 可说：在哪个群（说「别的群」不给群号）出现过几次、**聊过什么话题**、大概什么风格。
- 不说：原话、私聊/现实信息、好感度分数、跨群点名评价第三人；话题里混进第三个人的
  别名时，那一条话题直接丢弃。
- 注入口径句固定为「可以说在别的群见过、聊过什么；不复述原话、不给第三人评分」。
- 不因为认人把 A 群的人名无缘无故带进 B 群：只有命中才注入。

## 开关与回滚
- `socialV2.memory.people.enabled`，**默认 false**；关掉即：不记录、不注入、prompt 完全不变（无需回滚代码）。
- 记录与召回都受同一开关控制；`state/people.json` 仅在开启后生成。
- 单测全部用临时目录；线上 `state/` 由运行时自建。

## 失败降级
- 档案读坏/写失败 → 当空档案，只打日志，不影响聊天。
- 召回异常 → 返回空串（宁可不认，不编）。
- 别名太多/太长 → 截断规范化；未知名字 → 不注入，允许她说「不认识」。
