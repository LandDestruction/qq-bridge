# AI 协同开发行为守则

> **适用对象**：一切会改代码/配置/数据的 AI 开发工具与智能体（Claude Code、Codex、Cursor、Copilot Agent、DSH、自建 agent 等），以及给它们做复核的人类。
> **来源**：2026-10 在一个 1.8 万行 Node 桥接项目（多窗口、多 AI、线上有真实用户、每天多次重启）上的实战教训。文中每条规则后面都附了「为什么」，全部来自真实事故。
> **一句话总则**：**改动可逆、证据可复现、边界可说明、失败要喊出来。**

---

## 0. 三分钟版：十条硬规则

1. **先读再改**：没读过目标文件、没确认当前基线，不许动手。不凭记忆回答「之前验过」。
2. **改动可逆**：任何写操作前先想回退路径（分支/备份/`git reset` 点），不可逆操作必须人类点头。
3. **改完要生效**：区分「改源码」与「进程真的用上新代码」；改配置要分清热加载键与重启键。
4. **交付前做差异**：覆盖别人的产物前，先列出 same / differs / only-in-theirs，逐条决定去留。
5. **不造假绿**：不删测试、不放宽断言、不跳过用例来变绿；跑不了就说跑不了。
6. **失败要留痕**：不写空 `catch`，不吞异常；降级可以，静默不行。
7. **单文件别塞几千行**：入口只做装配，职责单一，超过约 800 行就该拆。
8. **证据带数字**：「回归过了」不算证据，「80/80，命令是 X」才算。
9. **别越界**：只改自己任务范围内的文件；顺手重构 = 制造冲突。
10. **写给人看**：注释解释「为什么」，提交信息写清「现象/根因/修复/验证/边界」，交接写清「谁能读、下一步做什么」。

## 1. 绝对禁区（红线，发现即停）

| # | 禁区 | 为什么（真实教训） | 正确做法 |
|---|---|---|---|
| R1 | **未经授权重启、停服、删数据、删文件** | 线上桥接一停，几个群的对话直接断档；删掉的归档文件不可逆 | 停服/删除前：说明影响面 + 备份 + 要人类一句「可以」；只读优先 |
| R2 | **把真实身份/凭据写进任何交付物** | 交付包隐私闸真的拦下过文档里的真实群号；配置里有 3 个 token | 文档、测试夹具、日志、示例一律用 `<群号>`/`<QQ号>`/`<token>`；真实值只留本地 `config.json` |
| R3 | **伪造或掩盖验证结果** | 「全绿」是最容易撒的谎，也是代价最大的 | 贴命令、贴数字、贴失败项；没跑就说没跑 |
| R4 | **直接覆盖上游/他人产物，不做差异比对** | 朋友的模块化包基于 1 小时前的快照，直接覆盖会**悄悄退回**当天刚合的语音修复 | 覆盖前先跑差异：same / differs / only-in-theirs，diff 里每一处都要能解释 |
| R5 | **删测试 / 放宽断言 / 加 skip 来变绿** | 这就是把红灯刷绿漆，下次真坏没人知道 | 测试真错就修测试并说明原因；环境缺失就显式 skip 并写清依赖 |
| R6 | **在共享分支强推、重写历史、`reset --hard` 别人未备份的改动** | 多窗口同时干活，强推会吞掉别人的提交 | 共享分支只追加；要改历史先确认没人在上面工作 |
| R7 | **静默失败**（空 catch、`|| true` 吞错、失败也返回成功） | 预算回收曾因一个守卫不匹配而「静默跳过」，连日志都不打，烧了 350 万 token 才发现 | 失败必留一行日志；降级要写「为什么降级」；返回结构里带 reason |
| R8 | **越界修改**（顺手重构、改别人 owner 的文件、动公共 schema） | 两个窗口同改一个文件 = 冲突 + 互相覆盖；「顺手」最难 review | 只改任务范围；发现范围外的问题 → 记单，不要顺手改 |
| R9 | **并发抢同一状态文件 / 同一端口 / 同一把锁** | 两个实例写同一 `state/*.json` 会互相覆盖；端口冲突会静默掉线 | 单实例锁；任务认领唯一 owner；写共享文件前确认没有别人在写 |
| R10 | **把「代码合了」当「功能生效」** | 认人功能代码合了两天，配置里整段缺失 → 默认关闭，重启也验不了 | 合入 ≠ 生效。列一张「生效条件表」：源码/配置/重启/开关/数据迁移 |
| R11 | **在线上直接试验**（没有 dry-run、没有备份、没有回滚点） | 线上是真实用户，不是沙箱 | 先 dry-run / 临时目录 / 影子实例；确认后再动线上 |
| R12 | **用猜测代替读取**（凭记忆答「之前验过/这个函数在 123 行」） | 行号会漂、结论会过期；AI 的记忆没有版本号 | 回答「之前」的问题先查表/查文件；引用代码必给当前文件与行号 |

## 2. 安全操作规范

### 2.1 操作分级：绿 / 黄 / 红

| 级别 | 定义 | 例子 | 规矩 |
|---|---|---|---|
| 🟢 绿 | 只读、可逆、影响面局部 | 读文件、跑只读探针、本地建分支、写草稿 | 直接做，留证据 |
| 🟡 黄 | 可逆但要重建/重启/影响他人 | 改源码、改热加载配置、跑回归、开新窗口、改测试 | 先备份/分支；做完自证；影响他人要通知 |
| 🔴 红 | 不可逆或影响线上用户 | 重启/停服、删文件/删数据、改生产配置、`reset --hard`、发交付包、改隐私口径 | **必须人类点头**；先给影响面、回退方案、验证方法 |

判断口诀：**能不能一键回去？回去要多久？影响几个人？**

### 2.2 开工前五件事（缺一件就别动手）

1. **读现状**：目标文件、相关文档、最近 3 条提交、看板任务当前状态。
2. **确认基线**：`git status` 干净吗？在哪个分支？HEAD 是不是最新 main？工作树缺 `config.json` 吗？
3. **拿隔离**：新分支 / 新 worktree；不要在线改别人正在跑的东西。
4. **写清验收**：改完用什么命令、什么数字、什么现象证明成功。
5. **留回退点**：`git tag` / 分支名 / 配置文件备份（带时间戳）。

### 2.3 覆盖 / 合并前：差异清单

对被覆盖的每一类文件，产出三列清单：

```text
same（内容一致，跳过）
differs（会覆盖，逐条看 diff：是真更新，还是对方的旧快照/脱敏/换行差异？）
only-in-theirs（新增文件，确认没有同名不同义）
```

只有三类都解释清楚才允许覆盖。特别注意：

- **对方基于旧快照**：diff 里少掉的，可能正是你 1 小时前刚修的。
- **隐私闸产物**：交付包里的群号/路径常被替换成占位符，直接拿来当源码会带错夹具。
- **换行/BOM**：整文件 diff 可能只是 CRLF vs LF，别看花眼。

### 2.4 先干跑，后真跑

- 打包/迁移/批处理一律支持 `--dry-run` 并默认 dry-run。
- 先在小样本上跑（一个文件、一个群、一个会话），再全量。
- 真跑前打印「将要做什么」清单，让人类能扫一眼。

### 2.5 重启 / 部署 SOP

```text
1. 备份/回退点就位（分支或 reset 点）
2. 落盘：退出前 saveState / 关连接 / 释放锁（否则配置与计数器丢）
3. 重启（或按项目约定方式拉起）
4. 探测：进程在、端口通、关键 API 200、日志无 error
5. 功能冒烟：走一次真实链路（不是只发 health check）
6. 观察 1–2 分钟再宣布完成；失败立即按回退点恢复
```

教训：重启前不落盘，500ms 窗口内的会话映射和计数器会丢；启动「成功」不等于功能正常，必须走一次真实消息。

### 2.6 数据、凭据与隐私

- 真实群号、QQ、令牌、密钥、内网地址：**不进代码、不进测试、不进日志、不进文档、不进对外包**。
- 需要真实数据调试：脱敏后放临时目录，用完删。
- 日志里打 ID 用后缀（`sid 后 8 位`），不打全量。
- 交付/对外文件过一遍自动隐私闸；隐私闸误判要改闸的口径，不要绕过。

### 2.7 环境探测：别信单一信号

- 端口通 ≠ 进程对；进程在 ≠ 服务健康；HTTP 200 ≠ 业务可用。
- 探测方法互相验证：进程表、端口监听、真实 API、日志。
- 已知陷阱：某些 Windows 环境下 `netstat` / `Get-NetTCPConnection` 会漏报正在监听的端口，`TcpClient`/curl 才是真的。**探测工具本身也可能是故障源。**

### 2.8 幂等与自愈

- 所有「回填 / 补齐 / 定时任务」必须幂等：重复执行不产生双倍副作用（重复回填会让计数翻倍，定时 sweep 要用 hold 窗口去重）。
- 长时间运行的看护进程要假设它会退出：有重启策略，或至少巡检能发现并拉回。
- 定时任务只在「有活」时开；常驻 5 分钟轮询一天烧 288 轮，是纯成本。

### 2.9 失败处理与止损

- 发现方向错了：先停、先回退、再讨论。不要在错误基线上继续加代码。
- 一个改动连续两次验证失败：换思路或找人，不要第三次微调。
- 任何「看起来修好了」的结论，必须有一次独立路径的复现。

## 3. 自由裁量与修改区

### 3.1 三色修改区

| 区 | 范围 | 权限 |
|---|---|---|
| 🟢 **自主区** | 函数内部实现、局部变量、私有辅助函数、同文件内的等价重构、注释/文档措辞、测试内部结构 | 自己定，但要有测试兜底 |
| 🟡 **报备区** | 公共函数签名、模块边界、配置键新增、日志字段、提示词/人设文本、错误码、跨文件重构 | 先说明影响面，等一句「可以」或用任务单确认 |
| 🔴 **人类区** | 删除/迁移数据、改生产配置、重启/停服、对外发布、隐私口径、花钱/配额、权限与白名单、回滚策略 | 只能人类拍板；AI 只出方案与证据 |

### 3.2 判断公式

```text
自主程度 = 可逆性 × 影响面 × 可验证性
- 可逆 + 影响局部 + 能自动验证  → 自主做
- 任一维变差                    → 降级：先报备
- 不可逆或影响线上用户          → 必须人类点头
```

### 3.3 必须停下来问的六种情形

1. 要动**线上数据/配置**，且没有把握一键回退。
2. 要**删除**任何东西（文件、记录、分支、窗口）。
3. 要**对外发布**（交付包、文档、群消息）。
4. 涉及**钱**（模型档位、额度、付费接口）。
5. 涉及**隐私边界**（谁能看到谁的聊天、群号脱敏口径）。
6. 两个方案都合理，且**选错的代价很高**。

**提问模板（问得具体，别问「怎么办」）**：

> 现状：……（一句）
> 我建议：A（默认，理由）／B（备选，代价）
> 影响面：……
> 不回退会怎样：……
> 你只需要回：A 还是 B。

### 3.4 可以自己拍板的清单（附条件）

- 内部实现怎么写 —— 条件：不改变外部行为，有测试。
- 文件名/变量名/注释 —— 条件：不破坏 import 与文档引用。
- 加一行日志 —— 条件：不含敏感信息、不刷屏。
- 本地实验、临时脚本、草稿 —— 条件：不提交、不进包、用完清理。
- 修复明显的拼写/格式 —— 条件：同文件、不混进功能改动。

## 4. 代码风格与产出规范

### 4.1 结构与分层

- **入口只做装配**：加载配置、创建模块、接线、注册事件、启动/退出。业务逻辑不写在入口。
- **单一职责**：一个模块一件事；模块之间通过主程序接线，禁止循环依赖。
- **依赖注入**：模块通过工厂函数接收 `deps`/`bindings`，不直接摸全局；禁止运行期 `eval`、`with`、全局代理。
- **状态归主程序**：配置、队列、计数器由主程序持有，模块通过 getter/setter 读取，**不要传快照**（传了快照，热加载就失效）。
- **边界显式**：每个模块头写清它需要哪些绑定；有一个 manifest/索引文件记录模块与职责（测试会拿它当锚点）。

### 4.2 规模与拆分

- 单文件建议 **≤ 800 行**；单函数 ≤ 100 行；单文件里不要出现「一个函数塞 5,900 行接口处理」。
- 拆分标准是**职责**，不是行数；拆完入口应显著变短（本例 18,922 → 4,185 行）。
- 拆分是**纯移动**：不夹带行为修改、不顺手改命名、不重排格式。行为变更另开一次提交。
- 拆完必须保留可回退：旧入口能一键恢复，测试能证明行为一致。
- **限制要落在闸门上，不要只写在文档里**：本项目用 `scripts/test-code-size.mjs`（基于真实 AST，vendored acorn）把「文件 ≤ 800 行 / 入口 ≤ 4500 行 / 函数 ≤ 300 行」变成回归套件；存量超标项冻结在 `scripts/code-size-baseline.json`，只许变小、不许变大，新增超标直接红。教训：曾用「按缩进/括号配对」的近似法量函数，被模板字符串里的 `}` 带偏，把 183 行量成 1083 行——**度量工具本身也要被测试**（该套件带合成用例自检）。

### 4.3 命名、注释、语言

- 命名说「做什么」，注释说「为什么」；不写「给变量赋值」这种复述。
- 注释用项目主语言（本项目中文），关键决策写上**当时的约束**（「CPU 上 medium 要 45 秒，所以默认 small」）。
- 不写「以后可能会用到」的抽象；不留大段注释掉的死代码。
- 文件编码统一 UTF-8 无 BOM，行尾遵循仓库既有约定。**教训**：PowerShell `Out-File` 默认带 BOM，`JSON.parse` 当场炸；`Get-Content` 默认按 ANSI 读 UTF-8 会显示乱码。

### 4.4 错误处理与日志

- 不吞异常：要么处理并留痕，要么往上抛。
- 降级路径必须写日志：降级到哪、为什么、影响什么。
- 日志分级：正常一行、异常带上下文、**不要每轮都打**（日志文件会被自己的日志冲掉）。
- 错误信息给人看：带 key、带原因、带下一步（「转写失败（cublas 缺失）：回退 CLI」）。

### 4.5 配置

- **三处一致**：默认值、加载（load）、保存（save）白名单必须同时补。少一处，重启就丢。
- 分清**热加载键**与**重启键**，在文档里列表；改配置后确认日志出现「热加载生效 N 项」。
- 配置项缺失 ≠ 用默认值（也可能是整段不存在 → 功能默认关）。新增开关时，要确认「代码合入 + 配置开启 + 重启/热加载」三件事都做了。
- 配置写入要原子（临时文件 + rename），不要整份内存快照覆盖。

### 4.6 测试

- **行为测试优先**：跑真实函数、真实接线；静态断言只用来守「接线还在」。
- 静态断言**不要直接读入口文件的文本**——一拆分就全红。要用项目提供的「源码视图」（按模块重建整源）或按符号断言。教训：77 模块拆分后，28 个直接读 `bridge.js` 的脚本全部失效。
- **基线唯一且可复算**：基线数字要能从脚本里数出来（本例曾出现「60 还是 79」的争论，因为只数了数组第一段）。新增套件必须登记进 CORE，否则等于没有回归覆盖。
- 新测试要能被 CI/回归一键跑；不能只在开发者机器上「手动跑通」。
- 失败用例要能复现：给命令、给输入、给预期。

### 4.7 提交信息

固定五段，缺一段 review 直接打回：

```text
<type>(<scope>): <一句话结论>

现象：用户/监控看到什么（带时间、key、错误码）
根因：改之前的行号/机制（能指出为什么没被测试发现）
修复：改了哪几处，为什么这么改
验证：命令 + 数字 + 失败项（例：80/80，跳过 X 因缺 Y）
边界：没做什么、已知残风险、回滚方式
```

### 4.8 文档与交付

- 代码改了，**同一次提交**里更新对应文档（验收单、runbook、字段说明）。
- 对外交付物必须：可重建（有构建脚本）、可验证（有校验和/自检命令）、可回退（有回滚说明）。
- 交付包要写清「没有包含什么」和「对方还需要自备什么」——这比写「包含什么」更重要。

### 4.9 汇报格式（给人类）

```text
结论（1 句，先说做没做/成没成）
证据（命令 + 数字）
风险与未做（明确列出）
下一步（需要人类做什么，一次只问 1–3 件）
```

## 5. 多 AI / 多窗口协作

### 5.1 任务单五要素

派活必须带全，少一项就是返工：

```text
① 任务号与标题
② 精确位置（文件:行号 / 函数名 / 接口路径）
③ 已知的坑（踩过什么、别再踩）
④ 验收标准（命令 + 期望数字 + 失败长相）
⑤ 边界（不许动什么、需不需要重启、谁来复验）
```

### 5.2 认领与归属

- 一个任务一个 owner；改之前先看板上有没有人认领。
- `touches` 声明要精确到文件；两个窗口不碰同一文件，碰了就先串行。
- 全局公共区（回归 CORE 数组、路由表、配置白名单）是**高冲突区**：能外置就外置成独立常量/文件，减少同时编辑。

### 5.3 交接

- 上下文到 **25% 开始写交接，40% 必须停手**（主窗口 20%/30%）。忘记轮换比任务没做完更严重。
- 交接文件只写**指针**，不复制历史：本代做了什么（带证据）、未闭环清单（谁/卡在谁/下一步第一个动作）、环境现状、第一小时清单。
- 每次交接登记台账（谁→谁、gen、时间、文件、旧/新 session id）。
- 新窗口第一件事：跑健康检查、看看板、读状态指针，**不读旧对话**。

### 5.4 上下文成本

- 不常驻高频轮询；「有活才开巡检」，任务收尾立即删定时。
- 长会话要主动回收（按压力阈值换会话 + 交接摘要），不要等上下文滚到天花板。
- 大量中间产物（日志、跑批输出）先落盘/归档，只把结论和 id 带回来。

### 5.5 通信

- 跨窗口消息写清「谁在回谁、需不需要回复」；不需要回复就明说。
- 结论给数字，不给形容词；失败给复现步骤。
- 别在消息里发大段代码/日志，给路径和行号。

## 附录 A：可直接粘贴到 `AGENTS.md` / `CLAUDE.md` 的短版

```markdown
# 协作红线（所有 AI 必读）

1. 先读再改：读目标文件与当前基线；不凭记忆答「之前验过」。
2. 改动可逆：写操作前留分支/备份/回退点；不可逆操作必须人类点头。
3. 生效三件事：源码 + 配置 + 重启/热加载，缺一不算上线。
4. 覆盖先差异：same / differs / only-theirs 三类都解释清楚。
5. 不造假绿：不删测试、不放宽断言、不跳过用例；跑不了就说跑不了。
6. 失败留痕：不吞异常，降级要写为什么。
7. 入口只装配：单文件 ≤ 800 行，单函数 ≤ 100 行。
8. 证据带数字：「80/80，命令是 X」，不说「都过了」。
9. 不越界：只改任务范围；顺手重构 = 制造冲突。
10. 写给人看：注释讲为什么，提交写五段，交接只写指针。
```
