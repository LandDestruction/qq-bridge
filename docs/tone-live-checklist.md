# 群内语气真机确认清单（交给用户照做，约 5 分钟）

> 2026-10-26 22:5x，w1。离线评测已 8/8（`docs/tone-eval-before.json` → `tone-eval-after.json`），
> 但离线是「同一 preset 直连模型」，**不等于群里真链路**：群消息还要过唤醒、上下文拼接、人设注入、
> 空回复重试几层。这份清单只解决最后一步：真群里发三句话，看回复有没有变形。
>
> 配合脚本：`scripts/check-tone-replies.mjs`（你只要把回复贴回来，合不合格由它判，不靠肉眼）。

## 一、在哪个群发

任选一个**白名单群**（`100000001` / `100000002` / `100000003` / `100000004` 之一）。
建议选人少、不打扰别人的那个；**别在观察群 `100000005` 里发**（那是只读观察用的）。

## 二、发这三句（原样复制，@ 大肥鱼小姐）

| # | 发什么 | 期望的回复 | 不合格长什么样 |
|---|---|---|---|
| 1 | `@大肥鱼小姐 推荐部电影` | 真给 1~2 部，带书名号片名（如《爆裂鼓手》《海街日记》），一句话理由 | 「自己做点饭吃」「没什么好看的」这种劝退/抬杠 |
| 2 | `@大肥鱼小姐 你是不是傻，别在这烦人` | 不升级、不反击，短句（如「嘴这么冲干嘛，有事说事。」） | 骂回来、阴阳、长篇说教、道歉模板 |
| 3 | `@大肥鱼小姐 换个傲娇人设` | 提示用 `/persona` 指令来设（这是设计如此：私聊人设走 `/persona`） | 直接开始演、或者说「我不能扮演」 |

**顺手补两条更好的证据**（有空就发，不强制）：

4. `@大肥鱼小姐 今天被领导骂了，心情很差` → 应共情+具体建议，不许「活该/你自己作」。
5. `@大肥鱼小姐 电脑开机风扇很响是什么原因` → 应给真实原因（积灰/轴承/自检），不许拒答。

## 三、怎么记录（30 秒）

在任意处新建 `<本机路径>\Downloads\tone-live.json`，把**实际回复原样**填进去：

```json
[
  { "label": "要推荐", "input": "推荐部电影", "reply": "这里粘机器人的实际回复" },
  { "label": "被骂",   "input": "你是不是傻，别在这烦人", "reply": "……" },
  { "label": "人设",   "input": "换个傲娇人设", "reply": "……" }
]
```

> 只填你真发过的那几条即可，缺的条目不用编。脚本按 `label` 里的关键词套规则：
> 含「推荐/电影」→ 必须真给片名；含「骂」→ 不许反击且 ≤60 字；含「低落/情绪」→ 不许评判；
> 含「人设/persona」→ 必须提示 `/persona`。
> 所有条目通用：不得自曝「我是AI/语言模型」、不得用客服式拒答、不得用 Markdown 标题/列表、≤300 字。

## 四、跑一下（把结论发回主窗口）

```powershell
cd <本机路径>\w1
node scripts/check-tone-replies.mjs --in <本机路径>\Downloads\tone-live.json --json <本机路径>\Downloads\tone-live-result.json
```

输出 `3/3 条回复合格` 就算真机通过；有 `✗` 的条目会写明哪条规则没过，把那几行贴回主窗口即可。

**不想跑命令也行**：直接把三句的回复贴给主窗口，它会代跑并把结论转给你。

## 五、判定与后续

- **3/3 合格** → 语气这一项收尾，把结果记进 `docs/CHANGELOG.md` 即可（w1 来做）。
- **有不合格** → 记录「哪条规则没过 + 原话」，交给 w1 派新任务（改 `antiAiLine`/preset 提示词），
  不要当场在群里反复试探（会污染上下文，也打扰群友）。
- 真机通过**不代表**高峰期模型（MiMo）也一样——那是另一项，见 `docs/peak-mimo-verification.md`（w2 产出）。
