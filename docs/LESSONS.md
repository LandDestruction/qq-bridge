# 开发教训日志

> 这份文档由 `scripts/make-lessons.mjs` 从 `client/07b-lessons.js` 生成，**不要手改**（改了下次生成会被覆盖）。
> 控制台里也能看：设置 → 教训。新条目加在 `client/07b-lessons.js`，然后重跑脚本。

## 桥接模块不是普通模块（这一条栽了三次）

- src/bridge/console/*.js 会被 scripts/bridge-source.mjs 用 vm.runInContext 裸执行，**不能写 import**。纯规则要写成独立 src/*.js，再由 deps.xxxPure 注入。
- 处理函数的 @bridge-function 标记必须**顶格**（脚本按 "\n// @bridge-function X:end" 精确匹配，带两格缩进就报 Missing function markers）。
- 路由要引用的函数必须在 src/bridge/manifest.json 的模块表里，否则报 Missing route X：先看你要挂的函数在哪个模块，不在表里就得先搬成 VM-safe 模块。
- VM 模块顶层的 const/let 和 src/bridge.js 顶层共用同一个全局词法作用域，**必须带模块前缀**（LIBFIND_/LIBDL_…），否则 Identifier already declared。
- 节点里的全局（Buffer / AbortSignal）在 VM 里不保证存在，要么 deps 注入，要么 deps.X || global。

## 体积上限是债务，不是审美

- scripts/test-code-size.mjs 有「文件行数上限 + 存量函数基线只许小不许大」。加功能前先想好往哪拆，不要等红了再抬上限。
- 抬上限要顺手写理由（注释或提交信息），并且**不要**用 --update 重写基线：它会冲掉别人写的 note 和条目。
- 函数超 300 行基本说明它在干两件事：外提纯逻辑，或者把子流程拆成模块级函数。

## CSS 有三个全站约定，破坏就要连坐测试

- @media (max-width: 768px) 全站只允许**一个**块（测试只读第一个），新的窄屏规则要并进既有的那块。
- nowrap 只允许给顶部导航胶囊，其余长文本一律换行（名单备注那一列就踩过）。
- 样式要同时照顾浅色、深色、玻璃态（[data-glass="on"]）和第五套 halo 皮肤，改一处至少扫一遍这四种。
- 皮肤要覆盖卡面样式时，把规则写在文件后半段也没用：后面的 `[data-glass="on"] .qdb-card` 同权重照样盖掉它——CSS 只比权重和先后，不比「谁更想覆盖」。皮肤覆盖统一放到文件末尾，并把选择器提到 `html[data-skin="x"][data-glass="on"]` 这一级；否则就是「明明写了却没生效」。

## 数据诚实：宁可少说，不可乱说

- 花费预警试发不能套「超了」的文案：7 块钱说超了 20，就是撒谎。要给手动试发单独一套「测试：现在用了 X，限额 Y」。
- 预警/通知别占冷却：手动试发不该把真正的升级提醒挤掉。
- 机器人说话里的「自报参数」（步数上限之类）只发群聊、不发私聊——模型自己报自己的参数不算可靠信息。
- 开发消耗 Token 这种数字要写清来源和时间点（本机 DSH 会话日志、统计到哪一天），别让人以为是实时值。
- 生成类功能降级/兜底不能在 toast 里闪一下就算告知：模型回 402 走本地兜底时，用户关掉提示就分不清这份结果是模型写的还是本地拼的。降级状态要常驻在结果旁边（收起提示后仍看得见），别只依赖一次性提示。
- 验证生成类功能要用**能分辨因果**的指标：把 top1 候选自己绑上去再看 `coverMatch:true`，那是自证——绑谁谁匹配。能分辨的是「标题分没变、总分却涨了」「封面指纹从空变成有值」「封面汉明距离 0」「`coverChecked` 从 0 变 4」。同理 `auto=true` 只能说明排序过了某条线，不能当成自动采纳的正确率；要评准确率得拿已知正确的号做对照。

## 交互细节：用户要的是物理直觉，不是特效

- 玻璃卡片不要「每隔一会儿扫过一道光」——那是机器在打卡。要的是通透感 + 跟随指针的细微光线变化（反光 + 对侧柔影 + 上沿高光）。
- 白底卡片上白光叠白光等于看不见：浅色主题里高光必须配一点点压暗（对侧柔影）才读得出来。
- 刷新要免令牌：壳子（HTML）本身不含数据，可以免令牌；数据接口照旧要。成功后种 HttpOnly Cookie，连 localStorage 都不用依赖。
- 空状态/错误态给「为什么 + 下一步」（Cookie 过期就说该重新贴），不要只丢一句 HTTP 400。

## 视觉与背景：先有明暗，再谈透明

- 把画布铺成整页背景后，卡片设成 19% 透明 + blur26 依然发黑：不是透明度不够，是背景图本身中部就是暗的，透出来的只能是暗。先让背景有大块明暗（柔光带、长流光），再谈「透上来」——透明度只搬运已有亮度，造不出亮。

## 真机验证永远比单元测试更早发现问题

- 改了 console-server.js 或 manifest 必须**重启桥接**才生效；只重拼 client.js 是看不到后端变化的。
- 单测绿了也可能在真机上 500：Object.create(request) 不能覆盖只读 getter，必须显式构造请求对象。
- curl 的 HEAD 会被鉴权挡住，返回 401 不代表静态资源坏了；要验就用 GET 看 content-type 和字节数。
- bash 的 /tmp 和 node 的 /tmp 不是同一个路径；落盘调试数据写到工程内 oil-ui-work/ 再读。
- Windows 上进程被杀是 exit code 1，没有信号标记——别把它当成命令失败。
- 装到线上的插件可能是旧复制件：`~/.dsh/plugins/<bundle>` 以前是手工 copy 的目录、不是 junction，仓库早就更新了，DSH 仍加载几个月前的旧插件（模型看得见早该隐藏的工具，每次调用都被 guard 拒，日志里只剩一句「不在白名单」）。判断：`lstat` 看它是不是链接，再拿同名文件与仓库比对 sha256；修法：`setup-dsh.mjs` 现在会把普通目录改名备份后重建链接（有测试断言「是链接」「备份存在」）。

## 工具边界：提示词先管，执行期兜底

- 工具边界要写进提示词，不能只靠执行期拒绝：guard 拒掉调用只是止损，模型还会一次次试（那次两天被拒 7 次，步数全花在撞墙上）。唤醒词里要明确「本场景没有这些工具，调用会被拒」，同时用 `ctx.tools.restrict` 把它们从 schema 里藏掉——两条都要，缺一个都会继续浪费步数。

## 提交与仓库纪律

- commit message 里不要写**反引号**：bash 会把它当命令替换，把正文吃掉（这个坑吃过两次）。长 message 写进文件用 git commit -F。
- oil-ui-work/ 是探针和截图目录，提交时一律排除：git add -A ':!oil-ui-work'。
- 生成物（public/client.js、changelog.js、安装包）要跟着源一起提交，否则下一个人装出来的还是旧的。
- 改 docs 里的交接材料要趁早：窗口一关，上下文就找不回来了。

## 外部世界：先试再说，别信文档

- BOOTH 的搜索只有 /ja/search/<词> 这一种 URL 形状能用，/search?q=、/zh-cn/search 全是 404——动手前先用 curl 试三种形状。
- 没有本地封面指纹时，权重必须按可用信号归一化，否则「标题 100% 一致」也永远过不了自动勾选线。
- 补封面必须挂到「件」上，不能只在目录里丢一张 `<boothId>.jpg`：多包目录（一个素材夹里 7 个 zip）会按名字相似度把图配给最像的包，配不上的当成散图（`src/library-asset.js:314-330` 的 loose），素材卡的 `thumbRel` 还是空、`localHash` 恒空，找号 `coverChecked` 永远是 0。正确做法是让封面跟主件同名、再加 `.thumbnail` 后缀（`<主件stem>.thumbnail.jpg`）——既配得上件，又被 `isThumb` 认出是封面；改完看 `thumbRel` 非空才算真挂上了。
- 版权与许可要写清：HALOFLUX 仅非商业、需署名；WorkBuddy2API 是 AGPL 且不随包；SnowLuma 不随包分发。致谢里也要写。
- 第三方页面结构会变：解析器要有 fixture 单测，改版后至少能立刻知道哪一片段断了。

## 白名单只认「字符串里有没有」是不够的

- 现象：给「打开链接」（`/api/open-url`）加了 booth.pm 白名单后，`booth.pm.evil.com`、`evil-booth.pm`、`https://booth.pm@127.0.0.1/` 这种写法看着像白名单，实际目标主机完全不是——前两个是别人的域名，第三个里 `booth.pm` 只是 userinfo（用户名），host 是 127.0.0.1。
- 根因：用 `url.includes('booth.pm')` 或字符串后缀比较，既不先解析出 hostname，也不看 userinfo、端口、协议。大小写和末尾点（`booth.pm.`）同样能骗过朴素比较。
- 以后怎么做：先 `new URL()`，只认 `https:`；hostname 做「等于白名单项」或「以 `.`+白名单项 结尾」的逐段判断，并统一小写、去掉末尾点（`src/bridge/console/open-url.js:23-31`、`:56-75`）。测试必须放五类反例：`booth.pm.evil.com`、`evil-booth.pm`、`https://booth.pm@127.0.0.1/`、`http://`、`127.0.0.1`，断言全拒——只测「正常链接能开」等于没测。

## 批量接口要逐条执行、逐条记账，别一条失败整批回滚

- 现象：已购库同步一次要翻 20 页、几百条；中途某页 429 或某条解析失败，如果整批 throw/回滚，前面抓的几百条白干，状态文件也写不进去。
- 根因：把「整批」当成一个事务，错误处理只放在最外层 try/catch；用户看到的只有一个「同步失败」，不知道抓到哪、哪条坏。
- 以后怎么做：循环里逐条计数 `added/updated/unchanged/failed`、错误收进 `errors[]`、每页 flush 一次；限速/登录失效用**停止码**表达（`stopped: 'rate_limited'|'max_pages'|'no_items'`、401 `needCookie`），已抓部分照常返回 `ok:true`（`src/bridge/console/library-purchases-sync.js:402-445`）。给用户的报告也要分项数字，而不是一句「同步失败」。
