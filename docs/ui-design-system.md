# UI 设计系统 v1.0（粉白）

> 任务：T15。适用对象：本项目的聊天机器人客户端外壳（控制台、运营面板、会话视图）。
> 本文是**唯一规范来源**；`public/ui-preview.html` 是它的可运行样张，`scripts/test-ui-design.mjs` 是它的静态闸门。
> 三个文件里的 token 值必须逐字一致——测试会拿样张里的真实 token 反算对比度，再和本文表格逐行对账，差 0.02 就红。

## 0. 设计意图（为什么长这样）

- **白底为主，粉只做点缀**。页面大面积是 `--ui-bg` / `--ui-surface`，粉色控制在视觉面积的 **10% 左右**：主按钮、当前导航项、徽章浅底、进度条、日志里的信息级别。粉色一多就变成"婚庆模板"，一少又会失去品牌识别。
- **粉有两种身份**：`#E8467C` 是"装饰与填充"（实心按钮底、进度条、状态装饰），`#C2185B` 是"文字与可点文字"。这不是审美选择，是实测结果——`#E8467C` 在白底只有 3.75，够不上正文 4.5，所以它被禁止做文字色。
- **信息密度靠留白和字重拉，不靠颜色和边框**。卡片只 1px 边框 + 1 级阴影；分隔靠留白，不靠分割线堆砌。
- **状态色只表达状态**。绿/黄/红永远出现在徽章、状态点、日志级别上，不做装饰底色。
- **可替换**：品牌名、色板、圆角全部走 token，换品牌只改一处（见 §9）。

### 1.2 深色

深色底 `#171216`、面 `#201A1E`、次级 `#2A2227`、边框 `#3A2E35`，正文 `#F7EEF3`，强调 `#FF7EB0`。深色下粉色变亮，因此**实心按钮的文字改成深色**（`--ui-on-accent` = `#241A20`），对比度 7.13；若仍用白字只有 1.9，直接不可读。语义色整体提亮，全部 ≥5.4（见 §2 表）。

## 3. 字体

`--ui-font-sans`：`system-ui, -apple-system, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', 'Noto Sans CJK SC', sans-serif`
—— 中文优先、零下载。**不引任何远程字体**（测试断言：无 `@font-face`、无 `url()`、无外链）。

| token | 字号 | 行高 | 用在哪 |
|---|---|---|---|
| `--ui-font-24` | 24px | 1.25 | 数字大指标、页面主标题 |
| `--ui-font-20` | 20px | 1.25 | 区块标题 |
| `--ui-font-16` | 16px | 1.25 | 卡片标题 |
| `--ui-font-14` | 14px | 1.55 | 正文默认、按钮、输入框 |
| `--ui-font-13` | 13px | 1.55 | 表格、会话列表、次要正文 |
| `--ui-font-12` | 12px | 1.75 | 时间戳、徽章、辅助说明（用 `--ui-text-meta`） |

字重只有三档：400 正文、550~600 强调、650~700 标题。不引第 4 档，因为系统字体里 500 与 600 的差异在不同平台会跳变。

等宽：`--ui-font-mono`，用于数字列、日志、群号占位。表格数字列右对齐不是必需的，但**同类数字必须同宽**（等宽体保证眼睛能上下扫）。

## 4. 间距

| token | 值 | 用在哪 |
|---|---|---|
| `--ui-space-1` | 4px | 图标与文字、徽章内边距 |
| `--ui-space-2` | 8px | 紧密行内、卡片内小节 |
| `--ui-space-3` | 12px | 卡片内边距（紧凑）、表格单元格 |
| `--ui-space-4` | 16px | 卡片内边距（默认）、区块间距 |
| `--ui-space-5` | 24px | 页面左右留白（桌面） |
| `--ui-space-6` | 32px | 区块之间的呼吸 |

规则：**只用这六个值**，不写 10px / 18px 这种中间值。间距的层次感靠"跳过一档"实现（4 → 12 → 24），不靠微调。

|---|---|

## 6. 组件

所有类名以 `qdb-` 开头，BEM 风格（`块__元素` + `块--修饰`）。每个组件在下表都有样张实例，测试逐个断言"CSS 有规则 + 标记里有实例"。

| # | 组件 | 类名 | 规格与状态 |
|---|---|---|---|
| 1 | 按钮 | `.qdb-btn` + `--primary/--secondary/--ghost/--danger`、`--sm` | 高 34（小号 28）；主操作用 primary，一屏最多 1 个；danger 只用于不可逆动作；`:active` 下沉 1px；disabled 用 55% 透明度且保留对比结构 |
| 2 | 输入框 | `.qdb-input` | 高 34，边框用 `--ui-border-strong`；占位符 `--ui-text-3`；错误态加 `aria-invalid` + 下方 `.qdb-field__err` 文案（不只用红边框） |
| 3 | 下拉 | `.qdb-select`（外套 `.qdb-select-wrap`） | 原生 select + 自绘箭头（`appearance: none`），保留系统滚轮与键盘行为 |
| 4 | 开关 | `.qdb-switch` | 38×22 轨道，checked 用 `--ui-accent-ink` 填充；原生 checkbox 保留在 DOM（视觉隐藏但可 Tab），焦点环挂在轨道上 |
| 5 | 复选框 | `.qdb-check` | 16×16，选中填 `--ui-accent-ink` + 白色对勾；文字与框用 flex 对齐，多行文字时框不跟着下沉 |
| 6 | 卡片 | `.qdb-card` | `--ui-radius-3` + `--ui-shadow-1` + 1px 边框；`__head` / `__title` / `__meta`；`--flat` 去掉阴影（用于卡片内再嵌卡片） |
| 7 | 表格 | `.qdb-table`（外套 `.qdb-table-wrap`） | 表头 `--ui-surface-2`、13px；单元格 nowrap（窄屏由外层横向滚动，不压列）；hover 行变色；数字列 `.qdb-num` 等宽 |
| 8 | 徽章 | `.qdb-badge` + `--success/--warn/--danger/--info` | 高 20、胶囊、12px；颜色 = 浅底 + ink 文字；**不承载可点性** |
| 9 | 状态点 | `.qdb-dot` + `--ok/--warn/--err/--idle`、`--live` | 8px 圆点；`--live` 有 2s 呼吸环（reduced-motion 下自动关）；必须配文字，不能只靠颜色表意 |
| 10 | 侧边栏项 | `.qdb-nav-item` | 当前项用 `--ui-accent-soft` 底 + `--ui-accent-ink` 字（不是整条粉色实心）；右侧可挂计数 |
| 11 | 标签页 | `.qdb-tabs` / `.qdb-tab` | 分段控件形态（灰底 + 选中白底浮起）；只切面板不改路由；`aria-selected` 承载状态 |
| 12 | 抽屉 | `.qdb-drawer` + `.qdb-scrim` | 右侧滑入，宽 `min(420px, 92vw)`，240ms；遮罩点击与 Esc 关闭，关闭后焦点回到触发按钮 |

| 14 | 空态 | `.qdb-empty` | 虚线边 + 24px 图标 + 一句人话 + 一个可选动作；文案要说"为什么空"，不写"暂无数据" |
| 15 | 加载骨架 | `.qdb-skeleton`（`--lg`） | 1.4s 流光；只在**首次加载**用，刷新用不遮内容的局部 loading；骨架形状要和真实内容一致 |

- 卡片里最多一个 primary 按钮；同一行按钮数量 ≤ 4。
- 徽章与状态点不叠用（徽章左侧已可带点，别两层都上色）。
- 表格里不塞按钮组，操作列只放一个 ghost 按钮（"详情"），其余进抽屉。
- toast 只做"事情发生了"的确认，不做需要用户决策的提示（那用抽屉或页内横幅）。

|---|---|---|
| `--ui-dur-1` | 120ms | hover、颜色变化、按钮按下 |
| `--ui-dur-2` | 180ms | 开关滑块、主题切换、toast 遮罩 |
| `--ui-dur-3` | 240ms | 抽屉滑入、进度条过渡 |
| `--ui-ease` | `cubic-bezier(0.2, 0, 0, 1)` | 统一 ease-out：起步快、收尾稳 |

规则：**只动 transform / opacity / background-color**，不动 width/height/top/left（会掉帧）。进入动画 ≤240ms，退出可略快。`prefers-reduced-motion: reduce` 时全部动画压到 0.01ms（测试断言这条媒体查询存在）。

## 8. 可访问性

1. **正文对比度 ≥4.5:1**，大字/图形/边界 ≥3.0:1 —— 见 §2 实测表，48 行逐行有数。
2. **焦点环 2px**：`outline: var(--ui-focus-width) solid var(--ui-focus)` + `outline-offset: 2px`，覆盖 `:focus-visible`。焦点环颜色本身 ≥5.4（浅）/7.8（深），不会在页面底色上看不见。
3. **键盘可达**：所有交互元素用原生控件（button/input/select/a），Tab 顺序即 DOM 顺序；抽屉打开后 Esc 可关、焦点进入抽屉、关闭后回到触发按钮；`a.qdb-skip` 提供"跳到主内容"。
4. **不只靠颜色表意**：状态点必配文字；错误输入框除红边还有 `.qdb-field__err` 文案与 `aria-invalid`。
5. **语义标签**：`nav[aria-label]`、`table` + `caption.qdb-sr`、`role="tablist"`/`aria-selected`、`role="progressbar"` + `aria-valuenow`、`aria-live="polite"` 的 toast 容器。
6. **触控目标**：按钮最小 28×28（小号），常规 34 高；相邻可点元素间距 ≥8px。
7. **主题不丢对比**：两套 token 都跑同一张对比度表，深色不是"把浅色反过来"。

## 9. 命名与可替换性

- 变量前缀 **`--ui-`**，组件类前缀 **`qdb-`**。两者都不含业务词（不叫 `--bridge-`、不叫 `.qq-`），保证这套 token 可以被外壳、运营台、独立页面同时引用。
- 品牌名 **「QQ DeepSeek Bot」是暂定名，只在单点定义**：
  - 样张里它只出现在 `<html data-brand="...">` 一处，页面上所有出现品牌的地方都是 `[data-brand-text]` 空容器，由 3 行 JS 填进去；
  - 规范里它只出现在本节；
  - 测试断言：样张中该字面量出现次数 **恰好 1 次**（出现在 2 处就红，避免"改一处漏一处"）。
- 换品牌的步骤（3 步，不改任何组件 CSS）：
  1. 改 `<html data-brand="新名字">`；
  2. 如需换色，只改 `:root` 与 `[data-theme='dark']` 两个 token 块的色值（几何/字号不动）；
  3. 跑 `node scripts/test-ui-design.mjs`，对比度表会被反算——不合格的行会直接红，**改完必须让表里的数字与实算重新对上**（用 `--emit-table` 重新生成贴回文档）。
- 换图标/插图：本版**不含任何图标字体或位图**，全部用文字符号（`☾ ☀ ▾ ✓`）与 CSS 形状，避免引入第三方素材。

## 10. 样张与三档断点

样张：`public/ui-preview.html`（单文件，零外链，≤120KB）。内含：色板、字体阶梯、间距/圆角/阴影、16 个组件实例、仪表盘样张（4 张状态卡 + 服务列表 + 会话列表 + 日志流）、深浅色切换按钮、抽屉与 toast 交互、实时视口宽度读数。

布局策略（为什么 360 不破版）：

| 宽度 | 行为 |
|---|---|
| ≥1280 | 侧边栏 220px 固定 + 内容区最大 1200px 居中；状态卡 4 列 |
| 768（≤900 断点） | 侧边栏变顶部横向条（可横向滚动），内容区单列起排；状态卡按 `minmax(220px, 1fr)` 自动折成 2 列 |
| 360（≤560 断点） | 侧边栏拆两行（品牌一行、导航一行自带横向滚动），页面左右留白降到 12px，状态卡 1 列，表格由 `.qdb-table-wrap` 横向滚动，品牌名超长省略；标题栏隐藏视口读数 |

不破版的三个技术前提（测试断言这三条存在）：① 网格用 `minmax(0, 1fr)`，长内容不会把列撑开；② 所有表格都有 `overflow-x: auto` 包裹层；③ CSS 里没有 `width: 1000px+` 这类固定宽度。

**三档断点的实测结果**（headless Chrome，`Emulation.setDeviceMetricsOverride` + CDP `Runtime.evaluate` 读 `scrollWidth`，浅/深各跑一遍）：

| 视口 | 页面 `scrollWidth` / 视口宽 | 越界元素（排除侧栏/表格/日志/抽屉这些"设计上就该滚动"的容器） | 表格内层 | 日志内层 |
|---|---|---|---|---|
| 360 | 360 / 360 | 0 | 439 / 334（横向滚动，符合预期） | 308 / 308（换行，无横向滚动） |
| 768 | 768 / 768 | 0 | 734 / 734 | 326 / 326 |
| 1280 | 1280 / 1280 | 0 | 1010 / 1010 | 464 / 464 |

判据是 `documentElement.scrollWidth === clientWidth`：页面级没有横向滚动条，就不存在"版被撑破"。另外人工看了 6 张整页截图（3 档 × 浅/深），没有溢出、截断或叠字。

**边界（老实写清）**：这是"结构性不破版"的证据，不是像素级回归——没有 golden image 基线，没在真机（真 iOS/Android）和 Safari 上验，也没跑 axe 之类的自动无障碍审计。要像素级基线，得等外壳（T16）落地后配视觉回归工具。

**默认主题是浅色**：不跟随系统 `prefers-color-scheme`——粉白是本设计的主态，深色是用户手动切的偏好（存 `localStorage`）。理由：多数用户第一次打开就该看到品牌色，而不是被系统深色带进一个没被拍板过的深色首屏。
