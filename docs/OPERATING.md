# 操作手册（OPERATING）

给「会用这台机器、但不想读代码」的人看。三份文档分工：

| 文档 | 回答什么 |
|---|---|
| **本文件 OPERATING.md** | 现在该点哪里、该跑什么命令 |
| `docs/DEGRADATION.md` | 三种降级态到底代表什么、什么时候叫醒 owner |
| `docs/FIXES.md` | 历史上修过什么（改代码的人才需要看） |

> 下文所有 `state/…` 都指**正在运行的那个桥接实例目录**下的 `state/`（本仓库是代码工作树，里面没有 `state/`，`config.json` 与 `state/` 属于运行实例）。

**遇到问题的固定顺序**：先看顶部状态条 → 点一次「一键自检」→ 再看 `state/bridge.log` 尾部（控制台「调试与运维」页也有同一份日志的尾部）。三步都记下来再去问人，比「它坏了」有用得多。

## 1. 一分钟上手

### 控制台在哪

浏览器打开 **http://127.0.0.1:3100** （端口取 `config.json` 的 `consolePort`，默认 3100；只监听本机 127.0.0.1，外网连不上）。

### 令牌从哪来

控制台要令牌才能读写。三个来源，按顺序试：

1. `config.json` 里的 `consoleToken` 字段；
2. 没配 `consoleToken` 时，桥接首次启动会在 `state/console-token` 里自动生成一串；
3. 已经进得去的话，在「访问与安全」页 →「控制台令牌」那张卡片可以改（输入新令牌点「保存令牌」，或点「生成随机令牌」），页面上会提示是否保存成功。

浏览器把令牌记在本地（localStorage 的 `consoleToken`）。令牌对不上时，所有面板都只显示「读取失败 / 未授权」，到「访问与安全」页重新粘一次即可，不用重启。

### 五个最常用面板

左侧导航按任务分组，日常只用得到这五个：

| 面板 | 用来看什么 |
|---|---|
| **运行总览** | 顶部状态条 + 「一键自检」+ 最近活动。**有事没事先看这一页** |
| **会话与审批** | 哪些群/好友在跟机器人对话、上下文会话 ID；AI 等待你回答的问题和待审批的工具调用 |
| **调试与运维** | 「重启桥接」「清空 QQ 聊天工作区」「测试发送」「出图测试」、最近日志（`state/bridge.log` 尾部） |
| **令牌与花费** | 花了多少钱、账本是否一致、上下文效率、导出 CSV |
| **二代仿真** | 开关仿真、唤醒策略、发送节奏、表情库（**改完要点保存，会先弹改动清单**） |

其余：人格与角色（人设）、一代仿真、黑话词库、访问与安全（白名单/令牌/安全）、工具参考。

## 2. 状态条怎么读

页面顶部一排六个小格。每个格子只有短词，鼠标悬停能看到「指标名：值」。

| 格子 | 绿 | 黄 | 红 |
|---|---|---|---|
| **模式** | 当前模式名（二代仿真 / 一代仿真 / 封闭 Agent / 聊天） | 读不到模式 | — |
| **DSH** | 就绪 | — | 未就绪（DSH 本体没起或连不上） |
| **SnowLuma** | 正常 | 未知 | 未连接 / 已连接但未接收 |
| **模型** | `provider/model` | `…（降级中）` | 读取失败 |
| **本地兜底** | 待命 · 成功 N · 失败 M | — | **接管中（已 X）· 成功 N · 失败 M** |
| **群聊** | 运行中 | 已暂停 | 读取失败 |

四种典型组合：

- **全绿**：正常，不用管。
- **模型黄（降级中）**：配置里的首选模型当前不可用，正在用备选模型顶着。群里还能回话但会慢一拍、价格也可能不同 → 去「运行总览 → 模型与思考强度」挑一个清单里真实存在的模型保存。细节见 `docs/DEGRADATION.md` 第一节。
- **模型黄 + 本地兜底红（接管中）**：首选和备选全挂了，现在是**本机的小模型在代班**（默认 `qwen3:8b`）。它能回话，但没有工具能力、不懂群聊协议、答得明显变笨 → 按降级手册第二节处理，持续超过 10 分钟就叫人。
- **DSH 红**：桥接连不上 DSH 本体，这时候任何「保存」都不会生效 → 走第 4 节的重启流程。

**账本那盏灯**在「令牌与花费」页（不在顶部）：绿「账本一致」、红「账本不一致：差 ¥X（Y%）」、灰「无法计算」。红灯的处置见降级手册第三节。

## 3. 故障速查表

### 3.1 机器人在群里不回话

| 步骤 | 做什么 | 看到什么说明什么 |
|---|---|---|
| 1 | 看顶部状态条 | DSH 红 / 模型黄 / 兜底红 都可能导致不回话 |
| 2 | 「会话与审批」页看有没有这个群的会话 | 没有 → 群号不在白名单；有 → 继续 |
| 3 | 看「群聊」格是不是「已暂停」 | 黄「已暂停」→ 到「二代仿真」页点「暂停二代 AI」那个按钮恢复 |
| 4 | 「一键自检」 | 有红项就按 3.6 处理 |
| 5 | 看 `state/bridge.log` 尾部 | 有「模型不可用 / 降级」→ 按降级手册第一节换模型 |

### 3.2 机器人回了一句报错，日志里有模型错误

说明消息发出去了，但生成那一步失败了（模型 id 错、额度没了、上游 5xx）。群里那句话只是后果，**真正要看的是日志里紧挨着的模型错误行**：

1. `state/bridge.log` 里搜 `模型` / `降级` / `provider`；
2. 状态条「模型」格若变黄，就是降级在用备选顶着 → 换一个模型（见降级手册第一节）；
3. 若日志说「配置的模型不可用，且没有可回退的模型」，说明备选链也空了，**必须立刻换模型**；
4. 「日志不再刷错误」不等于修好了：新版桥接会**记住不可用的模型 id 并在新会话里跳过**（不再每个会话先拿它失败一次），同一会话同一原因也只报一次。错误停了可能只是它不重试那个坏 id 了，群里可能仍在用备选模型回答——以状态条「模型」格和 `config.json` 里的值为准；
5. 桥接会**自动纠正模型并把正确值写回 `config.json`**（写前备份成 `config.json.bak-<时间戳>`）。状态条自己变绿了，说明配置文件被自动改过，值得打开看一眼是不是你想要的那个模型。

### 3.3 控制台面板全空 / 一直「加载中」

| 可能 | 怎么确认 | 怎么办 |
|---|---|---|
| 令牌不对 | 面板显示「读取失败 … 未授权」 | 「访问与安全」页重填令牌，刷新页面 |
| 桥接没在跑 | `http://127.0.0.1:3100` 打不开；`state/bridge.log` 很久没更新 | 按第 4 节重启 |
| 桥接在跑但某个接口挂了 | 「一键自检」里只有某一项红 | 看那一项对应的错误文本，见 3.6 |
| 刚改完配置还没生效 | 保存后提示「已保存」但数字没动 | 点顶部「刷新状态」（↻），或等 10 秒自动刷新 |

面板本身有失败可见性：读不到数据时会在该面板里写红字原因，**不会静默变成空白**——看到空白多半是整个页面没拿到令牌。

### 3.4 生图失败

在「调试与运维 → 出图测试」里试一张，能直接看到 HTTP 状态与耗时：

| 现象 | 含义 | 怎么办 |
|---|---|---|
| **403** | 缺 agent token（`reserved2 模式出图必须携带 agent token`），或出图功能被关 | 面板里贴上 agent token（贴一次会记住）；仍是 403 就看是不是 `imagegen.enabled=false` |
| **429（提示「出图冷却中，请 N 秒后再试」）** | 出图源有冷却（默认 45 秒/张）或撞了每小时上限（默认 10 张） | 面板会自动按 N 秒倒计时并禁用按钮，等它走完；不要连点，连点只会被继续拒 |
| **超时 / 504** | 出图源慢或不通 | 等几分钟再试；反复超时说明上游有问题，先别在群里用这个功能 |
| **500「出图失败：…」** | 取图或发送那一步出错 | 看 `state/bridge.log` 里同一时间的 `[draw] 工具出图失败` 行 |

生图 provider 目前**在界面上显示为「未知」**——桥接没有暴露 `imagegen` 配置的接口，这是已知限制。

### 3.5 账本不一致指示灯变红

含义：`已归属 + 未归属` ≠ `总花费`，差值超过 0.01。**多**出通常是重复计费，**少**出通常是漏归属。

1. 点「刷新」再确认一次（排除瞬时抖动）；
2. 差值小且稳定 → 记一笔，等修复，不用半夜处理；
3. 差值在两次刷新之间明显变大，或百分比超过 5% → 叫人，并用「导出按会话 CSV / 导出按模型 CSV」把当前窗口导出来一起发过去；
4. 灰灯「无法计算」表示接口没返回 `cost / attributedCost / unattributedCost`，**不代表一致**。

### 3.6 一键自检有红项

自检逐项请求六个接口，任何一项失败都不中断。红项就是「那个接口现在不能用」：

| 红项 | 对应接口 | 通常原因 |
|---|---|---|
| 桥接状态 | `/api/status` | 桥接刚重启还没就绪，等 10 秒再点一次 |
| 黑话词库 | `/api/slang` | `state/slang.json` 读不出来（文件损坏）；**不要手工改它** |
| 二代仿真状态 | `/api/socialV2/activity` | 二级仿真状态文件异常 |
| 会话映射 | `/api/sessions` | `state/sessions.json` 读不出来（降级为只读不写） |
| 用量账本 | `/api/tokens/summary` | 账本文件异常，或还没产生过用量 |
| 表情库 | `/api/stickers` | `state/stickers.json` 异常（表情可能发不出去） |

红项里写着的错误文本（HTTP 状态 + 响应片段）就是要贴给人的东西。

## 4. 重启与回滚

### 什么时候需要重启

- DSH 格变红且持续；
- 改完 `config.json` 后行为没变化；
- 面板大面积失败、自检多项红；
- 日志出现「只读降级」（黑话库 / 表情库 / 会话文件读失败）。

**能只重启桥接就别动整机。**

### 怎么重启

- **控制台**：「调试与运维 → 桥接控制 → 重启桥接」。由守护窗口启动时，重启后 5 秒自动恢复，页面会自动等它回来再跑一次自检。
- **命令行**（控制台打不开时）：在仓库目录跑 `restart.bat`；只想看它有没有活着，看 `state/bridge.log` 最后一行时间。
- **起不来时先看这两件事**：① 端口被占（`netstat -ano | findstr :3100`）；② `state/bridge.lock` 里记的 PID 是否还活着（见第 5 节第 2 条）。

### 重启会丢什么

- **配置、白名单、人设、表情库、黑话库、账本：不丢**，都在 `config.json` 和 `state/` 里；
- **正在生成中的那一条回复会丢**（会话上下文还在，下一轮照常）；
- 出图冷却、唤醒计时这类**内存状态会清空**（意味着重启后可以立刻再出一张图，也意味着当轮的冷却被绕过了）。

### 怎么回滚配置

1. 桥接**在启动时自动纠正模型**那一步写回 `config.json` 之前，会先备份成 **`config.json.bak-<时间戳>`**（同目录，例如 `config.json.bak-2026-10-25T08-30-00-000Z`）；
2. **控制台保存 / 切换模型不会自动备份** —— 所以在控制台做大改动之前，自己先复制一份：`copy config.json config.json.bak-manual-20261025`；
3. 出问题就把备份复制回 `config.json`（控制台的两个「保存」按钮都会动这个文件）；
4. **改完一定要重启**：配置是启动时读的，光改文件不重启不生效。

## 5. 不要做的事

1. **不要直接手改 `state/*.json`**。这些文件是桥接的内存状态落盘，运行中的进程会用自己的内存覆盖你的修改；更糟的是文件写坏后桥接会「降级为只读不写」，之后所有改动都不落盘。要改就通过控制台，或先停桥接再改、改完再启动。
2. **不要同时跑两个桥接**。桥接有单实例锁（`state/bridge.lock` 存 PID）：第二个会自己退出，日志写「已有实例在运行（PID …，锁文件 …）」，退出码 2；同一端口（默认 3100）也只能有一个监听者，两个进程还会往同一个 `state/` 互相覆盖映射。
   **只有确认前一个进程已经死了**（端口没被占、`state/bridge.log` 不再更新）才删 `state/bridge.lock` 再启动，别把"删锁"当成万能动作。
3. **不要用控制台的「清空 QQ 聊天工作区」试探**。它会把全部 QQ 会话归档并清空活动日志——那是给「要重来一次」准备的，不是排障按钮。
4. **不要在没有备份的情况下点「保存」大改二代仿真参数**。现在保存前会弹改动清单，请真的看一眼再确认。
5. **不要在群里直接问机器人「你还好吗」来判断它是否正常**——它回话不代表模型正常（可能在降级），看状态条和日志。

## 视频/语音转写失败（STT）怎么查

现象：机器人回「语音听不清/转写失败」，或群里的视频没有被解读。

1. 看桥接日志里 `[stt]` 与 `[video]` 两行：
   - `常驻服务转写失败（回退 CLI）：Library cublas64_12.dll is not found...`
     → 机器上有 NVIDIA 卡但缺 cuBLAS 12 运行库。**2026-11-02 起服务会自动永久降 CPU 重试**
     （`tools/stt_server.py` 的 `cuda_broken`），配置里也可以直接钉死 CPU：
     `socialV2.stt.service.device = "cpu"`（本机就是这个配置，冷启动约 10s，热转写 10s 音频约 3s）。
   - `转写(CLI) 耗时=… 字数=0 错误=语音听不清（high_no_speech）`
     → 先确认视频里真有人声；服务端现在遇到「0 段」会自动关掉 VAD 再转一遍（VAD 会把小声人声整段滤掉）。
2. 手动验证服务（默认 127.0.0.1:8791）：
   ```bash
   curl -s http://127.0.0.1:8791/health
   ```
   返回 `{"ok":true,"device":"cpu","loaded":true,...}` 即正常；`loaded:false` 表示还没被用过（懒加载）。
3. 想用 GPU：`python -m pip install nvidia-cublas-cu12 nvidia-cudnn-cu12`，再把
   `socialV2.stt.service.device` 改回 `auto`，重启桥接。装不上就保持 CPU，功能不受影响、只是慢 2~4 倍。
