## 看板：通过的契约（这些行为可以依赖）

1. **add → list 可见**，`owner`、`touches` 落盘；`touches` 以逗号分隔存成数组，**逐项 trim 且过滤空项**（`"a, ,b"` → `["a","b"]`）。
2. **状态折叠按事件顺序**：`claim→doing→blocked→done` 终态 `done`，`note` 取最后一次；计数行 `未完成 n / 完成 m` 正确。
3. **没有 add 先有事件**：任务以「(未登记)」占位显示，不会丢。
4. **参数缺失一律 exit 2**：缺 `--id`/`--title`/`--text`/`--to`、未知子命令。
5. **坏行容错**：半行、非 JSON 行被跳过，看板整体不挂（append-only + 读时折叠的直接好处）。
6. **空 brief / 空 owner 允许**：这就是 T99 那种空壳任务的来源，不报错（空 owner = 待领）。
7. **并发写安全**：6 进程 × 20 条并发 `add`，120 行全部可解析、120 个 id 全部读回，无撕裂行。
   → 六个窗口同时写看板不需要任何锁。
8. `tail` 默认 20 条，`tail n` 指定条数。
9. **`claim` 有归属校验**：任务已有 owner 且不是自己 → `exit 3`，owner/状态都不变；本人重复 claim 幂等；待领任务谁都能领。`doing/blocked/done` 不受此限（改派后原 owner 仍能收尾，不锁死）。
10. **改派只有主窗口能做**：`reassign --id X --owner wN --by main`（窗口自己 `--by w4` → `exit 3`，非法 owner → `exit 2`，不存在的 id → `exit 3`）。改派事件留在看板上可追溯，不改进度状态。
11. **`--owner` 白名单 `w1..w6`**：非法值（`w99`/`W1`/`w0`/`main`/`w7`）`exit 2` 且不落盘。
12. **任务排序＝前缀 + 数字**：`T2` 在 `T10` 前，`D13`/`M1`/`T*` 各自成组（旧实现字典序把 `T10` 排在 `T2` 前，也不能只比数字——否则 D/M/T 会打散）。

## 看板：五处缺陷（已全部修复）

`win6-board.mjs` 23:41 由 w4 按 D13 改完（旧文件备份在 `%TEMP%\win6-board.mjs.bak-20261026-234227`），
每一条都有对应回归用例；同一套件打旧实现是 **9/14**，红的就是这五条。

| # | 现象（修前） | 影响 | 修法（已落地） |
|---|---|---|---|
| 1 | 重复 `add` 同一 id 会把任务打回 `todo` | 重派/改派一撞号就把「干到一半」的任务抹掉（22:59 真发生过） | 重复 id → `exit 3` 且原任务不受影响（23:0x 已修，主窗口照本结论改的） |
| 2 | `claim` 无归属校验，任何人可把 owner 改成自己 | 改派靠自觉，撞车时互相覆盖且无通知 | `claim` 时若已有 owner 且 `by !== owner` → `exit 3`；并补 `reassign`（仅 `--by main`）作为唯一改派口 |
| 3 | 任务按字符串排序，`T10` 排在 `T2` 前 | 任务一多容易漏看 | 排序键＝(前缀, 数字, 原串)；前缀优先，避免 D/M/T 被打散 |
| 4 | `--touches` 不 trim，`"a, b"` 第二项带前导空格 | 按 touches 做冲突检测时匹配不上 | `.split(',').map(s=>s.trim()).filter(Boolean)` |
| 5 | `--owner` 不校验，`w99` 照收 | 手滑打错人，活没人接且不报错 | 白名单 `w1..w6`，非法值 `exit 2` |

> 改的是六个窗口共用的活文件：新文件先写到临时目录、跑通 14/14 才用 `Move-Item` 原子替换，
> 旧文件先备份。替换后立刻在真实看板上只读跑了一次 `list`（25 个任务正常折叠）+ `tail`，均 `exit 0`。
> 现在 `add --owner` 已不是改派手段（会被 #1 的重复 id 闸挡住），**改派一律用 `reassign`**。

## loop8（看护器）：通过的契约

`worker-loop8-selftest.mjs` 6/6，逐条复读确认：

1. 全静默必须**连续 8 轮**才退出（旧逻辑第 1 轮就退出，20:28 漏掉 20:43 的提交就是这么来的）。
2. 15 分钟（≈7 轮）后才来的提交仍能被接住。
3. 在途任务（脏工作树 / 产物未达标 / 冲突 / 回归失败）期间 quiet **永远不涨**。
4. 新提交或新合并那一轮把计数归零，攒够 8 轮才退。
5. `trackHeads`：第一次见到的 head 不算新提交；合并后 head 变了但 `main..分支` 已无增量也不算。
6. 退出消息可定制轮数。

## 结论与建议

- 看板的**核心可靠性（并发、折叠、容错）没问题**，可以放心让六个窗口并发写。
- 边界缺陷 #1-#5 已全部修掉并有回归用例兜着（14/14；旧实现 9/14 证明用例有效）。
- 剩下的风险是**绕过工具直接写 `workboard.jsonl`**（append-only 不校验内容）。目前只有工具会写；
  若将来有脚本要直接追加，必须自己保证「一行一个 JSON」和 `type/id/by/owner` 字段齐全。
- 改派现在走 `reassign --by main`；窗口不要再靠 `claim` 抢活，抢了会被 `exit 3` 明确拒绝。
- 窗口侧纪律可以放宽一点了：`--touches` 加空格不再有影响，但仍建议统一不带空格，便于人眼 diff。
