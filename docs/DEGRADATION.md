# 降级与兜底运维手册

这份文档给**值班的人**看，不写代码。三种降级态各自独立，可能同时出现；下面按「怎么发现 → 代表什么 → 该做什么 → 什么时候叫醒 owner」写。

判断入口只有两个地方，先记住：

| 地方 | 看到什么 |
|---|---|
| **顶部状态条**（每个页面最上方一行） | 模式 / DSH / SnowLuma / **模型** / **本地兜底** / 群聊，六个小圆点。绿=正常，黄=要留意，红=现在不对 |
| **用量页的「账本一致性」灯** | 灰=算不出来，绿=账本一致，红=账本不一致 |

---

## 一、模型降级（`degraded = true`）

### 怎么发现

- 顶部状态条「**模型**」那一格：正常显示 `provider/model`（例：`deepseek-official/deepseek-flash`）；
  **降级时变成黄色的 `…（降级中）`**。
- 日志里会出现「模型不可用，已切到备选」这类行。
- 群里表现：回复正常，但**慢一拍**——每轮都先尝试首选模型、失败、再落到备选。

### 代表什么

配置里写的首选模型**当前调不通**（改名了、下线了、额度没了、区域前缀不对）。
桥接按 `modelFallbacks` 这个备选清单逐个试，试通了就用它顶着回答。当前清单（`config.example.json`）：

```
workbuddy2api/deepseek-v4-pro
→ workbuddy2api/glm-5.3
→ deepseek-account/deepseek-flash
→ scnet/DeepSeek-V4.1-Flash-1017-Event
→ deepseek-account/deepseek-v4-pro   ← 官方 DeepSeek，固定最后兜底（配置项最后一行不参与 provider 交错）
```

**降级通知已改为只写日志**（2026-10-26）：桥接不再私聊管理员，
日志形如 `[模型] 已降级 workbuddy2api/x → deepseek-account/y（第 N 次，原因：…）`。
查降级请看日志或控制台状态条，不用再翻 QQ 私聊。

**关键点：这时群里是"能说话"的，所以看起来不严重——但它一直在用备选模型，质量和价格都和你以为的不一样。**
历史上出过的事故是：配置里写了一个已经不存在的模型 id（比如改成别的名字之前的旧 id），于是每轮都先失败一次再降级，白花一份请求、延迟翻倍。

### 该做什么

1. 打开「运行总览 → DSH 模型与思考强度」，看「**切换模型**」下拉里被标成「· 当前」的是哪个——那不是你配的，是备选在顶班。
2. 从下拉里挑一个**真实存在**的（清单是桥接报上来的，最可信），点保存。保存后提示会回读一次，显示「✅ 已切换为 `provider/model`」。
3. 保存后**再看一眼状态条**：「模型」格应该变绿且不带「（降级中）」。
4. 如果清单里根本没有你要的模型，说明模型池/账号侧有问题，别在控制台里硬填——填错会重演今天的事故。

> ⚠️ 不要用「手工输入」框去猜 id。那个框只在桥接版本太旧、拿不到清单时才出现，属于应急通道。

### 什么时候叫醒 owner

- 挑遍清单里的模型都还是「降级中」→ 说明不是单个模型的问题，是账号/额度/网关。
- 降级持续超过 **30 分钟**，或群里用户开始抱怨「答得不对/很慢」。
- 需要改 `config.json` 里的模型池或备选清单（这是 owner 的决定，不是值班能定的）。

## 二、本地兜底接管（`local.active = true`）

### 怎么发现

- 顶部状态条「**本地兜底**」那一格：
  - 灰色「**未启用**」= 这个兜底通道根本没开（默认就是关的）；
  - 绿色「**待命 · 成功 N · 失败 M**」= 开着但没在用（正常状态）；
  - **红色「接管中（已 X）· 成功 N · 失败 M」= 现在回答群友的是本地小模型**。
- 接管时状态条右侧还会把更新时间换成红字：「⚠️ 本地兜底接管中：<模型名> 正在代班（<地址>）」。
- 群里表现：能回话，但**明显变笨**——短、平、不接梗、不会用工具、可能答非所问。

### 代表什么

首选模型和所有备选**都调不通**（连不上、超时、或者模型侧报"不可用/容量不足"），桥接退到最后一道防线：一台本地跑的小模型（默认 `qwen3:8b`，走本机 ollama，10 秒超时，关掉思考以省时间）。

**能力边界（要如实告诉用户，别假装正常）：**

| 能做 | 不能做 |
|---|---|
| 用一段纯文本 prompt 生成一两句中文回复 | 调用任何工具（搜群记录、发表情、@人、语音、图片） |
| 维持基本礼貌和上下文里的最近几句 | 遵循完整的群聊协议（分条发送、引用、潜水策略） |
| 短句、简单问答 | 长上下文、复杂推理、多步任务、代码 |

也就是说：**它是"别让群里彻底没人说话"的保险丝，不是替代品。**

`成功 N / 失败 M` 是这次接管期间的累计——失败数在涨说明本地这套也不稳，那不是"等等就好"的状态。

### 该做什么

1. 先看「模型」格：模型降级 + 本地接管同时出现，说明**上游整条链路都断了**，照着上一节先修模型。
2. 确认本机 ollama 是否在跑（状态条红字里的地址就是它在用的地址）。
3. 判断要不要**主动停掉**：如果本地模型的回答已经在群里造成误导，宁可暂停二代仿真（「二代仿真」页的暂停开关），也别让它继续说。
4. 恢复后状态条应回到绿色「待命」，接管计数不再增长。

### 什么时候叫醒 owner

- **只要 `接管中` 持续超过 10 分钟就叫醒**——这是最后一道防线，正常情况下不该长时间停在这里。
- 本地模型已经开始在群里答非所问、被群友吐槽。
- `失败 M` 在增长（本地这套也撑不住了）。
- 需要改本地兜底的开关/地址/模型（属于配置变更）。

## 三、账本不一致（一致性灯变红）

### 怎么发现

- 「令牌与花费」页，四张指标卡下面一行：**红色「账本不一致：差 ¥X（Y%）」**，后面跟一句「已归属 + 未归属比总花费多/少出 ¥X。这通常意味着重复计费，请查看 P1 修复进度。」
- 绿色「账本一致」表示 `已归属 + 未归属 = 总花费`（差值在 0.01 以内）。
- 灰色「账本一致性：无法计算」表示接口没给全三个数（通常是桥接版本旧了），**不代表一致**。

### 代表什么

账本是这么算的：总花费 = 已归属到会话的花费 + 未归属的花费。
两边对不上，最常见的原因是**重复计费**：同一次调用被记了两遍（例如重试时把上一次的用量又加了一次），于是「明细加起来」比「总额」多。
也可能是漏记归属（某些调用没挂到任何会话上）。

审阅窗口实测到过一次：总花费 45.622，已归属 38.636 + 未归属 11.086 = 49.722，**多出 9%**。

### 该做什么

1. 先看差值方向和幅度：**多**出 → 大概率重复计费；**少**出 → 大概率漏归属。
2. 点「刷新」再确认一次（避免一次性抖动）。
3. 差值小且稳定（比如几分钱、长期不变）→ 记一笔，等修复版本，不用半夜处理。
4. 差值**持续变大**（每次刷新都涨）→ 说明还在重复记，会影响你对外报的用量和花费，按下面的标准叫醒。
5. 需要原始数据时用「导出按会话 CSV / 导出按模型 CSV」把当前窗口导出来，贴给 owner 或开发，比截图好用。

### 什么时候叫醒 owner

- 差值百分比超过 **5%**，或差值在两次刷新之间明显增长。
- 需要用这组数字对外报价/结算。
- 灯变成灰色「无法计算」并且持续（说明接口字段变了，账本口径可能整体失效）。

## 速查：三种状态的组合

| 状态条 | 含义 | 第一动作 |
|---|---|---|
| 模型绿 + 兜底「未启用」 | 正常 | 无 |
| 模型绿 + 兜底「待命」 | 正常（兜底已开但没用到） | 无 |
| 模型黄（降级中）+ 兜底待命 | 首选模型坏了，备选在顶 | 换一个真实存在的模型 |
| 模型黄 + 兜底**接管中** | 首选和备选全挂了，本地小模型在答 | **优先叫醒 owner**，同时考虑暂停二代仿真 |
| 模型绿 + 兜底接管中 | 少见：上游刚恢复但接管还没退 | 观察 5 分钟，不退就查日志 |
| DSH 红 | 桥接连不上 DSH 本体 | 按「重启桥接」流程处理，重启后会自动跑一次自检 |

> 重启桥接后，控制台会自动等它回来（最多 60 秒）并跑一次自检；自检有红项就说明重启后仍不正常，别以为"重启过了就好了"。
