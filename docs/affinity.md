# 好感度（0–100）：规则、上限、隐私边界

> 用户原话：「在直接问机器人好感度的时候，她会按照过往和现在的记忆给出评分，满分为 100 分。」
> 三条产品决策（用户已拍板）：**按人**（同一 QQ 号跨群/私聊统一）、**只能问自己**、
> **系统启发式打底 + 模型每轮微调，两者都限速**（防当场讨好）。
>
> 本文是给人看的规则说明书；接口签名见 `AFFINITY-API.md`，实现见 `src/affinity.js`。

## 1. 一句话：分数是已有记忆的数字视图

```
score = clamp(round(base + modelDelta), 0, 100)
```

- `base`：启发式底分，来自「今天来没来、有没有被 @、聊了多少」这类**可数**的事，每天只动一点；
- `modelDelta`：模型对这个人印象的微调，最多 ±3/次、每天累计 ≤10；
- `reasons`：最近 20 条具体依据（谁、什么时候、因为什么、加减多少），**数字必须能被它解释**。
- 没收录的人 = `start`（默认 50，即「刚认识，50 分起步」）。

## 2. 启发式底分：证据与每日上限

当天先把证据攒进「当天证据分」，**跨天时 base 只朝目标挪 10%**（`basePullRate`），
所以刷屏刷不出分：一天刷 50 条私聊和刷 20 条加的分一样多。

| 证据 | 每次 | 每天上限 |
|---|---|---|
| 当天有露面（当天第一条消息） | +1 | +1（一天一次） |
| 被 @ / 被引用 | +0.5 | +2 |
| 私聊消息 | +0.3 | +2 |
| 发表情 / 拍一拍 / 看图后接话 | +0.3 | +1 |
| 30 天没露面 | −5 | 一次空窗只扣一次 |
| 明确辱骂（配置关键词） | −1 | −3（当天扣满就不再扣） |

「10% 拉拽」的效果示例：某天证据合计 +6、底分 50 → 目标 56 → 结算后底分 **50.6**（不是 56）。
这样即使某人一天刷满，一天也只能涨 0.6 分；想上 70 分得靠几十天的真实互动。

实测节奏（`node --input-type=module` 跑 7 天模拟，每天 5 条消息 + 1 次被 @ + 1 次表情）：
**底分 50 → 51.08（约 +0.15/天）**。嫌慢就调 `evidence.basePullRate`（0.1 → 0.3 约快 3 倍），
这条是配置项，不用改代码。

## 3. 模型微调：五道闸都在桥接侧，不听模型自觉

新工具 `qq_affinity_shift(key, token, userId, delta, reason)`，`delta ∈ [-3, +3]` 整数，`reason` 必填 ≤40 字。

| 闸 | 规则 | 拒绝码 |
|---|---|---|
| 幅度 | \|delta\| ≤ `modelDeltaMax`（3） | `bad_delta` |
| 冷却 | 同一人 10 分钟内最多结算 1 次（`settleCooldownMs`） | `cooldown` |
| 日累计 | 每人每天 \|Σdelta\| ≤ 10（`modelDailyMax`） | `daily_limit` |
| 当场 | **这一轮正在被问好感度时，一律拒绝改分** | `asked_this_turn` |
| 在场 | 这一轮必须真有**该人的入站消息**（防自嗨） | `no_inbound` |

拒绝时**一个字段都不改**（不写 reasons、不更新分数），只返回原因文案给模型看。
另外 `enabled=false` 时全部拒绝（`disabled`），`reason` 空或超 40 字拒绝（`bad_reason`）。

## 4. 被问时怎么回答

命中 `queryKeywords`（默认：好感度 / 好感 / 几分 / 打分 / 喜不喜欢我 / 对我的印象）时，桥接往
该轮提示里注入 ≤300 字的片段：

```
【好感度】你对 小明 当前 62/100（底分 55 + 印象 7）。
印象里：① 上周一起斗图斗到半夜 ② 有人刷屏时你帮我顶了一句。
要求：按角色口吻报这个分数 + 挑 1~2 条具体理由；本轮不得调用 qq_affinity_shift；
分数就在上面，不要自己另编一个数字。
```

- **显示名**：优先群名片/群昵称（成员名缓存 → 台账里记过的名字 → 本条消息 sender → 同一人历史 sender），
  都取不到才退回 QQ 号。不再显示成 `小明(100000006)` 那种带号码的写法。
- **理由**：优先引用真实记忆——`qq_memory_event` 的共享事件（只认 global 与本会话 scope）和
  `qq_memory_append` 的 `memberImpression` 标签，最多 2 件；没有记忆时才退回「被 @ +0.5」这类计数器描述；
  两样都没有就老实说刚认识、从 50 分起步。整段仍 ≤300 字。

## 5. 隐私边界

- **只能报对方自己的分数**；被问第三人（「你对 XX 多少分」）→ 角色化婉拒，可以给态度不给数字。
- 唯一例外：`ownerCanQueryAll: true`（默认）时，**管理员在私聊里**问「所有人的分数」可以答。
- 任何列表接口都不吐分数（除 admin）；`state/affinity.json` 属敏感文件，不进包、不外发。
- 管理端名单：`GET /api/affinity?limit=50`（需控制台令牌）。**智能体调用一律 403 `admin_only`**——
  MCP 工具进程也持有控制台令牌，所以「有令牌」不等于管理员，必须显式拒绝带 `x-agent-call` /
  `x-agent-token` 的请求。返回 `{ ok, rulesVer, count, people[] }`，每人是
  `userId / name / score / base / modelDelta / lastSeenAt / 最近 2 条 reasons`，不含 `scope` 里的群号。
- 注入串（`privacyLine()`）里不含任何人名/QQ/分数，避免模型顺口把别人的分数说出去。

## 6. 数据与运维

- 存储：`state/affinity.json`，`version` / `rulesVer` / `people[userId]`；**原子写**（同目录 tmp + fsync + rename），
  写失败只清自己的 tmp，绝不留半截文件。
- 坏数据自愈：坏 JSON → 空库；坏条目（非对象、连 score/base 都没有）丢弃，好人保留。
- `rulesVer` 变更（改了评分口径）→ 载入时清空旧 `reasons`、按新规则重算分数，并记 `migratedAt`。
- 长期不互动：超过 **180 天**没动静的人自动删除（`prunePeople`）。
- `reasons` 环形保留最近 **20** 条。
- 跨天用东八区切（`tzOffsetMin: 480`），零点的边界不会把两天的证据算到一天里。

## 7. 两处与规格字面值不同（已报 W1，都是配置项，可改回）

1. **30 天未出现 / 辱骂是「立即扣分」**，不走 10% 拉拽。理由：`−1` 分要是也被 10% 稀释成 `−0.1`，
   惩罚等于不存在，用户完全无感。正证据才需要防刷屏。
2. **默认值取派单里的 `−5`（未出现）/ `−1`（辱骂，日上限 `−3`）**；规格 §3 写的是 `−2 / −3（上限 −4）`。
   两组都只是 `DEFAULT_RULES.evidence` 的默认值，改常量或写进 config 即可切换。

## 8. 怎么验

- 单测：`node scripts/test-affinity.mjs` → 26/26，全在临时目录，**不碰真实 `state/affinity.json`**。
- 重启后真机三条（需用户配合，重启前先问）：
  1. 群里 @ 她问「你对我好感度多少」→ 报数字 + 1~2 条具体理由，数字与 `/api/affinity`（admin）一致；
  2. 问「你对 XX 多少分」→ 角色化婉拒，不给数字；
  3. 同一人连发 20 条刷屏 → 分数不暴涨（对比前后）。
- 重启持久化：重启后再问一次，分数不变（`state/affinity.json` 里 `score/base/modelDelta` 原样读回）。
