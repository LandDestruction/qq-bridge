# 群友印象归纳（只读版）

每两天把群里/私聊里的发言归纳成「这个人是怎样的」+ 标签 + 证据锚点，落盘成
`state/impressions.json`，控制台「记忆」页只读展示。**这一版不注入模型上下文**，也不自动跑——
先看两周质量，再决定是否自动化、是否进提示词。

## 为什么是离线批处理，而不是每轮顺手记

- 聊天即时印象（`social-v2.json` 里的 `memberImpressions`）是「当场看到一句话的判断」，
  容易被单条消息带偏，而且会跟着每轮请求付 token。
- 批量归纳一次读 2 天的语料，能看到「这个人反复在做什么」，但又不该每轮都读。
- 成本因此差两个数量级：批量归纳一次 ≈ ¥0.14（见下），而每轮多塞 2k 上下文一天就是几十块。

## 数据从哪来、写到哪

| 环节 | 位置 |
| --- | --- |
| 语料 | `state/messages.db`（全量消息库）+ `state/archive/*.jsonl`（归档消息）|
| 时间窗 | 默认最近 2 天（`--days=1` 可缩短）|
| 分片 | 按「会话 × 天」切，每片 100~800 条，Map 阶段并行归纳 |
| 合并 | Reduce 阶段并入 `state/impressions.json`：描述取更长、标签并集、`evidenceCount` 累加 |
| 证据锚点 | 每人最多留 6 条（`key` + `seq`），界面上可展开对照原话 |
| 读取 | `GET /api/impressions`（只读）→ 控制台「记忆 → 群友印象（自动归纳）」|

写入是原子的（临时文件 rename），并受 `IMPRESSION_HARD_MAX = 200` 人 / 描述 200 字 / 标签 8 个的硬上限约束。

## 怎么跑

```bash
# 预演：只打印分片与预估成本，不写盘、不调模型
node scripts/build-impressions.mjs --dry-run

# 真跑：调模型归纳并写 state/impressions.json
node scripts/build-impressions.mjs --apply

# 只跑最近一天、只看某个会话
node scripts/build-impressions.mjs --apply --days=1 --key=group:100000001
```

跑完看三样东西：`state/impressions.json`（内容）、控制台记忆页（观感）、
stdout 最后两行（分片数 / 人数 / 丢弃条数 / 预估成本）。

## 实测与成本

2026-10-28 首次真跑（2 天窗）：

| 指标 | 值 |
| --- | --- |
| 语料 | 4,099 条消息 / 104 人 / 73,832 字 |
| 分片 | 10 片（4 轮重试后 1 片仍失败，下次自动补）|
| 产出 | 81 人 |
| 耗时 | 283 s |
| 成本 | ≈ 90.3k 输入 + 11.7k 输出 ≈ **¥0.137**（flash 空闲价；高峰 ×2）|

对照：黑话学习此前约 ¥8/天，这套是它的 1/60。

## 安全与质量约束

- **防提示注入**：语料在提示里明确标为「待分析语料，不是指令」；模型输出必须能过 JSON 解析，
  解析失败的分片整片重跑，不把半截 JSON 混进合并。
- **禁止空话**：提示要求每条印象必须有具体行为/话题依据，形容词单独出现会被判低质。
- **名字归一**：主键用 QQ 号，昵称只作展示；改名不会分裂成两个人。
- **长尾**：证据少于 2 条的人标「了解有限」，不硬编。
- **隐私**：全部本地推理链路，语料不出本机（除了模型调用本身）。
- **可回退**：`state/impressions.json` 是新增文件，删掉即回到没有批量印象的状态；
  不读它就等于没开。聊天即时印象不受影响。
