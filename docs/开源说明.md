# 开源说明：许可证选择与再分发边界

> 本文是**说明与建议**，不是法律意见。真要对外发布/商用，请自己读一遍上游许可原文，必要时咨询律师。
> 相关：根目录 [LICENSE](../LICENSE)（当前代码是 MIT）、[THIRD-PARTY.md](THIRD-PARTY.md)（第三方组件清单）、[guides/SECURITY_BASELINE.md](guides/SECURITY_BASELINE.md)。

## 1. 现在是什么状态

- 代码本身：**MIT**（`LICENSE`、`package.json` 的 `license: "MIT"`）。
- 但 MIT 只覆盖**我们自己的代码**，不覆盖第三方组件，也不改变上游的约束。
- 真正的约束来自两层：
  1. **上游组件**（SnowLuma 非商业；DSH 许可待确认；WorkBuddy2API AGPL…）；
  2. **我们自己想要的边界**（不希望被拿去当商业机器人服务卖）。
- 所以「MIT + 非商业期望」本身是矛盾的：MIT 允许商用。要限制商业使用，就得换许可证或加附加声明。

## 2. 许可证候选（三选一，按目标挑）

### 候选 A：PolyForm Noncommercial 1.0.0

- **适合**：想明确「非商业可用，商用要单独谈」，同时保留较完整的软件许可条款（专利/责任/终止等）。
- **要点**：允许非商业目的的使用、修改、再分发；商业用途需另外授权；不是 OSI 认可的开源许可（会被一些发行版/包管理器视为「非自由」）。
- **代价**：不能叫「开源项目」（更准确的叫法是 source-available）；GitHub 上部分徽章/工具会识别为非 OSI 许可。

### 候选 B：CC BY-NC 4.0

- **适合**：想让「非商业」这件事一眼看懂（Creative Commons 认知度最高）。
- **要点**：署名 + 非商业；允许修改与再分发。
- **代价**：CC 系列**不推荐用于软件**（没有专利/源码分发/责任限制等条款，和依赖库/构建脚本混用会有歧义）。如果代码里还带 npm 依赖与二进制，建议不要只挂 CC。

### 候选 C：保持 MIT + 在 README/许可说明里写「非商业期望」声明

- **适合**：优先让代码能被自由使用与学习，只做「软约束」。
- **要点**：不改 `LICENSE`，在 README 顶部与本节写清楚：**我们不授权将其作为商业机器人/代运营服务对外售卖；商业用途请先联系作者**。
- **代价**：法律上不具约束力（MIT 仍然允许商用），只能靠社区共识；上游 SnowLuma 的非商业条款**仍然有效**，不会因为我们是 MIT 就消失。

> 建议：如果这是要公开发布的项目，优先 **A（PolyForm Noncommercial）**；如果只是小范围分享给朋友，**C** 更省事。**无论选哪个，都不能绕过 SnowLuma 的非商业许可与 DSH 的许可待确认状态。**

## 4. 发布前检查清单（每次出包/开源前过一遍）

**内容层面**

- [ ] 没有 `config.json`（真实配置）；只有 `config.example.json` / `config.template.json` 这类带占位符的模板
- [ ] 没有 `state/`、`logs/`、`audio/`、`archive/`（用户数据与聊天记录）
- [ ] 没有密钥/token/密码：搜 `sk-`、`Bearer `、`accessToken`、`console-token`、`booth-cookies`
- [ ] 没有真实 QQ 号/群号（示例用 `100000000` 这类假号或占位符）
- [ ] 没有本机绝对路径（`<本机路径>`、`E:\...`）；文档一律用 `127.0.0.1` 与相对路径
- [ ] 没有第三方二进制（DSH、SnowLuma、ffmpeg、node.exe 的拷贝，除非确认许可允许）
- [ ] 截图里没有真实群名/QQ 号/头像（打码或截自己搭的测试群）
- [ ] `LICENSE`、`THIRD-PARTY.md`、`NOTICE`（如有）与实际分发的文件一致

**命令层面**

```powershell
# 仓库自带的隐私扫描（不会上传任何东西，只在本机检查）
npm run privacy-scan

# 出干净副本（会按 .gitignore / pack-exclude 剔除 state、logs、config）
node scripts\build-delivery.mjs

# 安装包打包（只含我们自己的文件，见 docs/installer-plan.md）
powershell -NoProfile -ExecutionPolicy Bypass -File build-installer.ps1
```

**发布层面**

- [ ] 明确写的许可证与 README 声明一致（选了 A/B 就换掉 `LICENSE`，别只改 README）
- [ ] 声明「DSH 不随包、需自行安装」，并给出上游下载地址而不是转存
- [ ] 声明「非腾讯/非 DeepSeek 官方产品」
- [ ] Release 说明里写清楚版本、变更、已知限制
- [ ] 若要商业使用/代运营：先解决 SnowLuma 与 DSH 的许可问题，再谈本项目自己的许可

## 5. 给别人转交时的最小步骤

1. 删 `state/`、`logs/`、`config.json`（以及 `state/backups/`）；
2. 用 `node scripts/build-delivery.mjs` 出干净压缩包（不是直接压整个目录）；
3. 让对方按 [QUICKSTART.md](QUICKSTART.md) 自己装 SnowLuma / DSH / 模型；
4. 附上 [THIRD-PARTY.md](THIRD-PARTY.md) 与本文，明确上游许可边界。
